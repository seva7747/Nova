# Nova

A working website prototype of an Alexa-style voice assistant named **Nova** — plug it in, say "Nova," and ask
it things like *"what's the weather,"* *"when does Chelsea play next,"* *"check my email,"* or *"schedule a
dentist appointment for 4pm this Thursday."* This isn't a mockup: the demo on the page runs a real full-duplex
voice session (OpenAI's GPT-Live-1) that delegates every request to a separate tool-use loop on GPT-5.4-mini,
with Gmail and
Google Calendar wired up through [Composio](https://composio.dev).

It's meant as the **software proof-of-concept before building the physical hardware** — get the brain, the
voice, and the integrations feeling right first.

## How it works

```
you 🎙 → "Nova" wake word (Picovoice Porcupine on-device, browser recognizer as fallback)
       → opens a persistent full-duplex voice session: OpenAI GPT-Live-1
             — listens and speaks at the same time, no separate record/upload step
       → the instant you finish a thought, GPT-Live-1 delegates it to our backend
       → GPT-5.4-mini (decide: answer directly, search the web, or call a tool)
             ├─ web search:  weather, sports, news, prices...    → searches live and answers,
                                                                      no key beyond the OpenAI one
             └─ slow tools:  Gmail / Calendar (via Composio),    → Nova acknowledges immediately
                              call-a-restaurant (simulated)          ("sure," "one sec"), then
                                                                      speaks the real answer
       → GPT-Live-1 speaks the answer back over the same open session
       → session stays open (no wake word needed) until things go quiet, then hangs up
```

The instant acknowledgment ("Sure." / "On it.") isn't generated by the brain — it's GPT-Live-1's own voice
layer, instructed to say something short the moment it delegates, the same way Alexa's chime signals "I heard
you" before she answers. The brain's actual answer arrives and gets spoken separately, whenever it's ready.

## Model choices, and why

| Stage | Choice | Why |
|---|---|---|
| Wake word | Picovoice Porcupine (on-device), browser `SpeechRecognition` as fallback | Runs locally, listening for "Nova" — free, and no API call happens until it actually fires. |
| Listening & speaking | OpenAI — GPT-Live-1 | A persistent, full-duplex WebRTC voice session — replaces a separate transcription call + a separate text-to-speech call with one always-on connection that also handles turn-taking/interruption natively. Runs in "client delegation" mode: it never answers on its own, it hands every request to our backend. |
| Reasoning / tool routing | OpenAI — GPT-5.4-mini, via the Responses API | Fast, inexpensive, and reliably good at multi-tool tool-use, which is the hard part of an assistant like this. A separate model and a separate API call from the voice layer above it — same key, different bill. |
| Integrations | Composio | One SDK/auth layer in front of Gmail, Google Calendar, and hundreds of other tools, instead of hand-rolling OAuth for each. |
| Live info (weather, sports, news...) | OpenAI's hosted `web_search` tool | The model runs a real search itself and reads the results before answering — no separate API/key, and it isn't limited to just weather and sports the way a hand-picked API would be. This tool is the reason the brain runs on the Responses API rather than Chat Completions; it doesn't exist on the latter. |

### Why there's no dedicated weather or sports API

Earlier drafts of this called OpenWeatherMap and TheSportsDB directly. That's gone now — a bare language model
(no tool) will happily *guess* a plausible-sounding forecast instead of admitting it doesn't know, which is easy
to mistake for a real answer once. OpenAI's Responses API has a hosted `web_search` tool: give the model the
tool, and it runs a real search and reads the results before answering — for weather, sports, news, prices,
anything that changes over time. It's billed per search on top of normal token costs, and needs no extra key
beyond `OPENAI_API_KEY`.

### A note on GrubHub specifically

GrubHub doesn't expose a public consumer API, and it isn't a toolkit Composio offers — so "order food" isn't
wired to anything real here. The example you gave that's closest to this — *"call up Armadillo Willy's to
reserve a table"* — isn't an API call for anyone, even Alexa; it's a phone call. So that flow is fully built as
a UX demo (`call_restaurant` in `backend/src/tools/restaurant.ts`): Nova acknowledges, "calls," and returns a
simulated confirmation. To make it real, that one function is where you'd plug in a voice-calling platform
(Bland AI, Vapi, Retell, etc.).

## Why GPT-Live-1 instead of record → transcribe → speak

Nova originally ran a classic pipeline: record a whole utterance client-side, upload it, transcribe it (Groq
Whisper), run the brain, synthesize the reply (ElevenLabs), download and play the audio. That's three sequential
network services per turn, plus a "wait for silence, then upload" step before anything could even start — and
barge-in (interrupting Nova mid-sentence) had to be faked with a mic-volume threshold.

GPT-Live-1 replaces the whole voice layer (listening, speaking, turn-taking, interruption) with one persistent
WebRTC session that does all of it natively and concurrently. It does **not** replace the brain or Composio — it
runs in "client delegation" mode, meaning it hands the user's words to our backend and just speaks back
whatever `runConversationTurn` (unchanged) returns. See `backend/src/services/liveDelegate.ts`.

**Trade-off:** it's billed per minute of *open session* ($0.05/min, billed per second) rather than per request,
so Nova opens a session only after the (free) wake-word detector fires, and hangs it up again after a few
seconds of silence — see the "Follow-up listening" setting.

## Getting it running

You'll need **Node.js 18.17+** and accounts (most have a free tier) for:

1. **OpenAI** — https://platform.openai.com/api-keys (needs access to GPT-Live-1). One key covers all three
   OpenAI surfaces Nova uses: the voice session, the brain, and the brain's hosted web search.
2. **Composio** — https://composio.dev → Settings → API Keys
3. **Picovoice** (optional but recommended) — https://console.picovoice.ai, free account → Porcupine → train a
   "Nova" keyword for "Web (WASM)" → drop the downloaded `.ppn` into `frontend/public/` as `nova.ppn`. Without
   this, the wake word falls back to the browser's built-in (less reliable) speech recognizer.

Weather and sports don't need their own key — they run through the model's own hosted web search.

### Setup

```powershell
# from the nova/ folder
npm install

# fill in your keys
Copy-Item backend\.env.example backend\.env
Copy-Item frontend\.env.example frontend\.env
# now open backend\.env and paste your API keys in

npm run dev
```

This starts the backend on `http://localhost:8787` and the frontend on `http://localhost:5173`. Open the
frontend URL, click the orb to "plug in" Nova (grants mic access), then say **"Nova"** followed by your
request. There's no typed-text fallback — Nova is voice-only, the same as real hardware would be.

### Connecting Gmail / Google Calendar

Once `COMPOSIO_API_KEY` is set, the "Connect your accounts" section on the page will let you connect Gmail and
Google Calendar — it opens Composio's hosted OAuth flow in a new tab. Once connected, just ask Nova to use them:
*"check my email"*, *"what's on my calendar today"*, *"schedule a dentist appointment for 4pm this Thursday."*

Want more tools? Composio's catalog (https://composio.dev/toolkits) has hundreds of apps — add a toolkit's slug
to `COMPOSIO_TOOLKITS` in `backend/.env` (comma-separated) and it becomes available to Nova automatically, no
code changes needed.

> **Heads up:** Composio's SDK evolves fairly often. `backend/src/services/composio.ts` is written against
> their documented v3 TypeScript SDK shape, with a comment at the top pointing at their docs — if a method name
> has moved since, that's the one file to check. GPT-Live-1's REST contract is even younger (shipped Sept 2026)
> — `backend/src/services/live.ts` has a comment on how to re-verify it against the real API with `curl` if it
> ever starts rejecting requests again.

## Project layout

```
nova/
  backend/    Express + TypeScript API — the tool-use loop (incl. web search), Composio, restaurant demo
              tool, and the GPT-Live-1 session/delegation handling (services/live.ts, services/liveDelegate.ts)
  frontend/   Vite + React + Tailwind — the product page + the working demo (hooks/useNovaLive.ts is the WebRTC
              transport, hooks/useNovaConversation.ts is the state machine around it)
```

## What's next (hardware phase)

Once the software feels right: swap the browser wake-word listener for an on-device model (Picovoice Porcupine,
already wired up here, or similar) running on the target hardware (e.g. a Raspberry Pi class board with a
far-field mic) — the rest of this pipeline (GPT-Live-1 ↔ brain ↔ tools) carries over largely unchanged, just
driven from firmware/an on-device app instead of a browser tab.
